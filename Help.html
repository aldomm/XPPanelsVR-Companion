What is included

One Mac application contains Display Bridge, hardware-encoded outside video, an optional virtual ultrawide monitor, a small control preview, and the XPPanelsBridge simulator plugin. No BetterDisplay, DeskPad, WebFMC, compiler, Python, CMake or SDK is required on a customer's Mac.

You supply macOS 15 or later, X-Plane, an appropriately licensed supported aircraft with working detached pop-outs, XPPanelsVR on Vision Pro, and a private local network. This preview has been developed against X-Plane 12 on Apple silicon; Intel and X-Plane 11 require separate qualification. Aircraft licensing and pop-out restrictions still apply.

Aircraft compatibility

Display Bridge is for use only with X-Plane running a ToLiss A320 or A321 aircraft. Other aircraft and simulators are not supported. Working detached operating-system pop-out windows are required. The current Mac setup has been tested with X-Plane 12.4.3 and ToLiss A320 v1.2.1; A321 and other aircraft versions still require separate verification.

Display Bridge is an independent AldoApps product, not affiliated with or endorsed by ToLiss or Laminar Research. Their names identify compatibility only. You must obtain the simulator and aircraft licences separately and comply with their restrictions.

Install

  1. Run the Companion installer. It places only the app in Applications; it does not alter X-Plane, approve permissions, or start sharing.
  2. Quit X-Plane. For migration, quit the old standalone Display Bridge and DeskPad after quitting X-Plane. Keep the old applications until the new setup is verified.
  3. Open Companion from Applications. Choose the folder containing X-Plane.app and Resources, then Install / Update Plugin. A recognized previous plugin is backed up outside the simulator folder. Other plugins and aircraft are not modified.
  4. Allow Screen Recording. If macOS requests it, quit and reopen Companion. Allow Local Network and firewall access on your trusted home network. No Accessibility permission is required for the preview's pointer handoff.
  5. In Outside View, choose High Quality (5120 x 1440) or Performance (3840 x 1080). Create Monitor before launching X-Plane. Physical monitors also work; no virtual display is necessary in that case.
  6. Launch X-Plane. In Settings > Graphics select XPPanelsVR Outside for the main simulator view at the chosen resolution. Do not mirror it to the MacBook display. Companion does not rewrite simulator preferences.
  7. After starting Sharing, use Instruments > Open Missing Displays. Individual open buttons are also available. These use ToLiss's popup commands without needing to click the cockpit. Existing open displays are skipped. Load the supported aircraft first; absent or stale popup-state readings are not guessed.
  8. Start Sharing, and enable Allow Outside View. Enter this Mac's displayed LAN IP in XPPanelsVR. Video/instruments use TCP 49200, the command plugin uses UDP 49001, and native X-Plane uses UDP 49000. Do not use 9090.
  9. In Companion > Connection, approve your headset's address. Then reconnect Outside View and toggle Cockpit Displays off/on in the headset. Approval lasts only for this sharing session.
  10. For High Quality, select 5120 x 1440 / 30 HEVC in the headset. Verify that actual source/video dimensions are 5120 x 1440. A quality maximum does not upscale a smaller source.

Instrument placement

Choose your physical Mac screen under Instruments > Instrument display. Allow Window Placement requests macOS Accessibility permission for Companion. Then Move Displays Here arranges identified instrument windows on that screen, never the outside-view display. Sizes are retained, so windows may overlap on a small MacBook screen. Do not minimize the source windows. With permission granted, Open Missing Displays also attempts placement.

A Please wait message and spinner remain visible in Companion during automatic opening, placement and resizing. Companion's menu-bar item also says Please wait... while X-Plane is in front. Setup can take about a minute, sometimes longer. Leave the mouse untouched until the message clears and the final result appears. The status identifies the current step; it is not a percentage or a guaranteed completion time.

Newly opened displays receive default native window sizes: PFD, ND and ECAM 600 x 628 (square content plus title bar), both MCDUs 652 x 1028, and ISIS 420 x 448. These are the same window-point units shown in the Instruments table, not Retina backing pixels. Use Default Sizes reapplies them to windows already open; Move Displays Here preserves custom sizes. Accessibility permission is required for sizing.

A full-height MCDU can extend below a shorter Mac screen. Its title bar remains accessible and independent-window capture includes the whole window, not just the on-screen portion. When native mouse resizing is needed, Companion may briefly stage a window on a taller display before returning it to the instrument screen. This can briefly cover Outside View during setup. If no display is tall enough, or X-Plane rejects the size, Companion reports an incomplete operation instead of silently shrinking the window. MCDU capture allows up to 1080 pixels on its longest side; its headset crop still contains the LCD only.

When pop-outs overlap, default sizing temporarily stacks them in a clear area of the other monitor, working from the frontmost window backwards. It returns them in reverse order so their title bars remain reachable. Outside View may be covered briefly during setup. Escape stops immediately; if windows remain on the temporary monitor, use Move Displays Here to return them. No simulator controls are clicked to uncover windows.

The aircraft must support detached native pop-outs. If a popup opens inside X-Plane instead, use the control preview to detach it. In the ToLiss ISCS, use its pop-out option where available and enable Save Popup Config On Quit. ToLiss documents closing via the native window's close button to retain detached mode; clicking the display face to close may return it to in-simulator popup mode. Companion does not force undocumented popup states or bypass licence restrictions.

If X-Plane does not expose movable windows to Accessibility, Companion temporarily uses the mouse to drag verified native title bars and resize corners instead. Leave the mouse alone until placement finishes; Escape cancels. Covered controls are skipped, not clicked through. The floating preview hides during placement and returns afterward. If placement reports an unavailable title bar or resize edge, uncover the window and retry, or resize it manually. The pointer returns to its original position afterward.

Daily flight

Open Companion, create the saved-resolution monitor, then launch X-Plane. Start sharing, open missing displays and approve the headset. The floating preview stays above normal windows without changing the virtual monitor's resolution. Reopen it from the PiP icon on any Companion page, the menu-bar app, or View > Show Control Preview (Command-Shift-P). Click the preview to move the pointer to that location on the virtual display; the next click operates X-Plane. Move the mouse back to the physical display as usual. Outside View > Show Mouse Pointer makes the mouse visible in the headset and defaults on. Hide the cursor for flight if desired. Hide/close the preview during flight to stop its capture workload.

Closing the main Companion window keeps its menu-bar app running. Stop Sharing immediately disconnects viewers. Quit X-Plane before disconnecting a virtual monitor or quitting Companion. Companion deliberately prevents losing a monitor while the simulator uses it. Capture and sharing are never automatically enabled at login.

Quality and recovery

  • At 160 degrees, a 5120-wide source supplies 32 horizontal source pixels per degree; 3840 supplies 24. This is not headset optical resolution. Higher quality does not guarantee higher simulator FPS.
  • If movement stutters, compare X-Plane FPS and headset decoded/uploaded FPS separately. Exit X-Plane before changing the virtual monitor to Performance. There is no unvalidated automatic benchmark or disruptive in-flight fallback.
  • If X-Plane is clipped, stop the flight, quit X-Plane, create exactly one correctly sized monitor, and reselect it in Graphics. Do not repeatedly remove/add monitors with the simulator running.
  • If TCP 49200 is occupied, quit the old bridge. Do not run two bridges. Outside View permits one viewer; do not run a second video test while the headset is connected.
  • If instruments wait after a bridge restart/approval, toggle Cockpit Displays off/on. Check that pop-outs remain open and that macOS recording permission is still granted.
  • Virtual displays use a private macOS interface. A future OS update may break it; physical-display capture is the fallback. No BetterDisplay purchase is required.

Updates and removal

Quit X-Plane first, then quit Companion before installing a newer package. Reopen Companion and choose Setup > Install / Update Plugin before relaunching X-Plane. Installing the Mac application does not update the simulator plugin by itself. Setup compares both version and payload hash and reports when an update is available. Version 0.1.1 includes the new rudder-trim hold/release commands required by the current headset app.

Settings offers Restore Previous Plugin, Remove Plugin and Show Plugin Backups. If custom files or altered plugin binaries are found, automatic replacement/removal is refused. Backups are in ~/Library/Application Support/XPPanelsVR Companion/Plugin Backups. Switching signing identities can require fresh Screen Recording and Accessibility approval.

To remove everything: quit X-Plane, remove the plugin in Settings, turn off Open at Login, disconnect the monitor, quit Companion and move the app to Trash. Saved plugin backups are retained; remove them manually only when no longer needed. No aircraft or simulator preference is deleted.

Privacy and support

Only explicitly shared simulator windows are served to approved LAN addresses. The optional preview captures the selected display locally and may show other apps there. Avoid private information on a shared simulator window. Current HTTP/UDP transport is unencrypted; IP approval is not secure pairing and does not protect the simulator's UDP ports. Never expose ports to the internet.

Export Diagnostics creates a small local text report for your review. It does not upload it, include screenshots, or copy simulator logs. Support: aldoapps@gmail.com.
